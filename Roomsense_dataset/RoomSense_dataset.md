# **RoomSense dataset**

## **บทคัดย่อ**

เก็บข้อมูลจากห้องประชุมจำลองเป็นเวลา 4 วัน (วันละประมาณ 3 ชั่วโมง) ที่อัตรา 2 ครั้งต่อวินาที ผู้ทดลองจำลองการใช้ห้องด้วยตุ๊กตากระดาษ 0–6 ตัว ตามตารางจองห้องที่สุ่มไว้ล่วงหน้า รวม 44 รอบ (146 ครั้งที่ตุ๊กตาเข้าห้อง) และทดสอบเซนเซอร์ไฟไหม้ 8 ครั้ง (ไฟแช็ก 4, แก๊ส 3, ธูป 1\) 

ได้ข้อมูล 86,384 แถว ใช้ 3 วันแรกเป็นชุดฝึก และวันที่ 4 ซึ่งมีสภาพแสงต่างออกไปเป็นชุดทดสอบ

## **1\. วัตถุประสงค์**

1. สร้างชุดข้อมูลเซนเซอร์สำหรับเทรนโมเดลที่ตัดสินว่า "ควรจ่ายไฟให้ห้องหรือไม่" (power\_on)

2. วัดการตอบสนองของเซนเซอร์ไฟไหม้ (flame sensor, MQ-2) ต่อไฟ แก๊ส และควัน เพื่อออกแบบ safety rule

3. ทดสอบว่าโมเดลที่เทรนจากบางวัน ใช้กับวันที่สภาพห้องต่างออกไปได้หรือไม่

   

## **2\. คำถามและสมมติฐาน**

|  | คำถาม | สมมติฐาน |
| :---- | :---- | :---- |
| H1 | กล้องร่วมกับเซนเซอร์ประตูทำนาย power\_on ในวันที่ไม่เคยเห็นได้แม่นแค่ไหน | ได้ F1 ≥ 0.90 |
| H2 | อุณหภูมิและความชื้นช่วยทำนายการมีคนในห้องจำลองหรือไม่ | ไม่ช่วย เพราะตุ๊กตาไม่ปล่อยความร้อนและความชื้น |
| H3 | MQ-2 และ flame sensor ตรวจจับการทดสอบไฟไหม้ได้ทุกครั้งหรือไม่ | alarm ติดทุกครั้ง ภายใน 20 วินาทีหลังเริ่มทดสอบ |

## **4\. อุปกรณ์และการติดตั้ง**

![อุปกรณ์][image2]

**วัสดุ**

* ESP32 DevKit (logger), ESP32-S3 \+ กล้อง (ตรวจนับตุ๊กตาด้วย FOMO), LED strip 5 V พร้อมสวิตช์

* เซนเซอร์ 7 ตัวตามรูป, laptop สำหรับบันทึก serial และ event logger

* อุปกรณ์ทดสอบ: ไฟแช็กแก๊ส, ธูป, ถังน้ำหรือถังดับเพลิงขนาดเล็ก

**การต่อระบบ**: logger อ่านเซนเซอร์ทุก 500 ms แล้วพิมพ์ 1 บรรทัด CSV ทาง USB serial (115200 baud) ไปที่ laptop ส่วนบอร์ดกล้องส่งจำนวนตุ๊กตาที่ตรวจพบมาให้ logger ทาง UART ประมาณ 3 ครั้งต่อวินาที และเก็บภาพนิ่งทุก 10 วินาทีลง SD card เพื่อตรวจย้อนหลัง

### **4.1 Schema ของข้อมูล**

![ที่มาของข้อมูล][image6]

ข้อมูลมี 2 ทางที่มาบรรจบกันในไฟล์ `train.csv` / `test.csv`: **ค่าเซนเซอร์** (feature) มาจาก ESP32 logger ทาง USB serial ทุก 0.5 วินาที และ **label `power_on`** มาจากปุ่มที่ผู้ทดลองกดใน event logger บน laptop ทุกครั้งที่คีบตุ๊กตาเข้า-ออก (ไม่ได้มาจากเซนเซอร์ตัวใด จึงไม่รั่วจาก feature)

1 แถว = 1 ครั้งที่ logger อ่านค่า (ทุก 500 ms)

| คอลัมน์ | มาจาก | ตำแหน่งในกล่อง | ชนิด / ช่วงค่า | ความหมาย / ค่าพิเศษ |
| :---- | :---- | :---- | :---- | :---- |
| `day` | ใส่ตอน parse | — | 1–4 | วันที่เก็บ (1–3 train, 4 test) |
| `boot` | ใส่ตอน parse | — | 0–1 | เพิ่มขึ้นเมื่อบอร์ดรีเซ็ตและ `timestamp_ms` เริ่มนับใหม่ (วันที่ 2) |
| `timestamp_ms` | ESP32 `millis()` | — | ms, ~2,500–11,000,000 | เวลานับจากบอร์ดเปิด ปกติห่างกัน 500 (1,000 = บรรทัดหาย) |
| `mq2_raw` | MQ-2 (AO) | ใต้ฝากล่อง | ADC 12-bit, 289–1,847 | แก๊ส/ควัน ห้องว่าง 300–360, ช่วง warm-up ถึง ~590 |
| `flame_do` | Flame sensor (DO) | ผนังหลัง หันหาช่องหน้าต่าง | 0/1 | active-low: **0 = เจอไฟ** |
| `digital_do` | IR obstacle FC-51 (DO) | ข้างกรอบประตู ยิงขวางประตู | 0/1 | active-low: **0 = มีวัตถุผ่านประตู** |
| `temp_c` | DHT22 | ผนังข้าง กลางความสูง | °C, 25.8–33.2 | อ่านทุก 2 s จึงซ้ำ 4 แถว, `nan` = อ่านไม่สำเร็จ |
| `humidity` | DHT22 | ผนังข้าง กลางความสูง | %RH, 49–71 | เหมือน `temp_c` |
| `temp_f`, `heat_index_c`, `heat_index_f` | คำนวณใน firmware | — | float | `temp_c × 1.8 + 32` และสูตร Adafruit `computeHeatIndex()` |
| `analog_1_raw` | LDR (AO) | ผนังข้าง หันเข้าในกล่อง | ADC, 211–1,201 | แสง: ค่ามาก = มืด, LED เปิด ~280, ปิด ~750–1,000 |
| `analog_2_raw` | Gray sensor TCRT5000 (AO) | พื้นธรณีประตู หันขึ้น | ADC, 282–3,297 | ปกติ ~300, มีมือ/ตุ๊กตาผ่าน 1,500–3,300 |
| `alarm` | คำนวณใน firmware | — | 0/1 | `flame_do == 0` หรือ `mq2_raw > 700` |
| `person_count` | กล้อง ESP32-S3 + FOMO (UART ~3 fps) | กลางฝากล่อง มองลง | 0–6 | จำนวนตุ๊กตาที่กล้องเห็น, **`-1` = กล้องไม่ส่งข้อมูล** |
| `power_on` | event log ของผู้ทดลอง | — | 0/1 | **label**: 1 ตั้งแต่ `fig_in` ตัวแรก ถึง 30 s หลัง `fig_out` ที่ทำให้ห้องว่าง |

**ไฟล์ในชุดข้อมูล** (`box_dataset/`)

| ไฟล์ | เนื้อหา |
| :---- | :---- |
| `raw/day{N}_{date}.csv` | log ดิบจาก serial 1 ไฟล์ต่อวัน (มี boot log, header ซ้ำ, บรรทัดขาดครึ่ง) |
| `train.csv`, `test.csv` | raw ที่ parse แล้ว + `day`, `boot` (วัน 1–3 / วัน 4) |
| `events/day{N}_events.csv` | event log ที่ผู้ทดลองกด: `fig_in`, `fig_out` (พร้อม `count=N`), `led_on`, `led_off`, `arrange`, `*_test_start/end`, `board_reset` — ที่มาของ label |
| `ground_truth/day{N}_truth.csv` | จำนวนตุ๊กตาจริง, สถานะ LED, label ทุก 0.5 s (ใช้ประเมิน/วาดรูปเท่านั้น ห้ามใช้เป็น feature) |
| `sessions.csv`, `known_issues.csv` | สรุปแต่ละวัน และปัญหาที่พบพร้อมเวลา |

## **5\. การออกแบบการทดลอง**

### **5.1 โครงสร้าง**

* **4 session** (วันละ 1 session) แต่ละวันมีสภาพห้องแล็บต่างกัน ถือเป็นตัวแปร block

* แต่ละ session มี **11 รอบจอง** (episode) คือช่วงที่มีตุ๊กตาในห้องต่อเนื่อง 1 กลุ่ม

* กำหนดให้มี **กรณีพิเศษ** กระจายอยู่ในหลายวัน เพื่อให้ข้อมูลมีสถานการณ์ที่ยาก (หัวข้อ 5.3)

* **ทดสอบไฟไหม้ 1–3 ครั้งต่อวัน** ทั้งตอนห้องว่างและตอนมีคน (5 จาก 8 ครั้งทำขณะมีตุ๊กตาในห้อง)

* ใช้วันที่ 1–3 เป็น **train** และวันที่ 4 เป็น **test** โดยเลือกวันที่มีแดดเป็นชุดทดสอบ เพื่อดูว่าโมเดลรับมือกับสภาพที่ไม่เคยเห็นได้หรือไม่

### **5.2 การสุ่มตารางจองห้อง**

ก่อนแต่ละ session ผู้ทดลองสุ่มตาราง scenario ล่วงหน้าด้วยกติกาต่อไปนี้ แล้วทำตามนาฬิกา

| ขั้น | กติกา |
| :---- | :---- |
| รอบแรกเริ่ม | 3.2–4.7 นาทีหลังเปิดระบบ (หลัง warm-up) |
| จำนวนตุ๊กตาต่อรอบ | สุ่มจาก 1, 2, 2, 3, 3, 4, 4, 5 (บางรอบกำหนดเป็น 5 หรือ 6 ตัว) |
| ระยะห่างการเข้าของแต่ละตัว | 3–15 วินาที |
| มาสาย | โอกาส 20% ต่อตัว มาช้ากว่ากำหนด 1–3 นาที |
| ระยะเวลาใช้ห้อง | 5–13 นาทีต่อรอบ |
| การออก | ส่วนใหญ่ออกพร้อมกันตอนจบ ห่างกันตัวละ 2–10 วินาที |
| ออกก่อน | โอกาส 12% ต่อตัว (เฉพาะรอบที่นานกว่า 6 นาที) |
| ขยับตุ๊กตา | เฉลี่ย 0.7 ครั้งต่อรอบ มือในกล่อง 3–7 วินาที จำนวนตุ๊กตาไม่เปลี่ยน |
| เปิด LED | 1.5–6 วินาทีหลังตุ๊กตาตัวแรกเข้า |
| ปิด LED | 2–8 วินาทีหลังตัวสุดท้ายออก (รอบที่ "ลืมปิดไฟ": 2.5–6 นาที) |
| ห้องว่างระหว่างรอบ | 3–9 นาที |
| จบ session | ห้องว่างอย่างน้อย 4 นาทีหลังรอบสุดท้าย |

### **5.3 กรณีพิเศษที่กำหนดไว้**

| กรณี | จุดประสงค์ | วัน |
| :---- | :---- | :---- |
| ออกแล้วกลับเข้ามา (ออกไป 40–120 วินาที) | จำนวนคนลดแล้วเพิ่มกลางรอบ | 1, 3, 4 |
| ลืมปิดไฟ | LED เปิดค้างขณะห้องว่าง (label \= 0\) | 2, 3, 4 |
| กลุ่มถัดไปเข้าทันที (10–25 วินาที) | label ต้องเป็น 1 ต่อเนื่องข้าม 2 รอบ | 2, 4 |
| แวะสั้น (ตุ๊กตา 1 ตัว ประมาณ 2 นาที) | ช่วง label \= 1 ที่สั้นมาก | 3, 4 |
| เต็มห้อง 6 ตัว | กล้องนับยากที่สุด | 2, 3, 4 |
| ทดสอบไฟขณะมีคน | alarm เกิดพร้อม label \= 1 | 1, 2, 3, 4 |

## **6\. ขั้นตอนการทดลอง**

![ขั้นตอน][image3]

**ก่อนเริ่ม**

1. วางกล่องบนโต๊ะห้องแล็บ ห่างหน้าต่างประมาณ 2 m ตรวจว่าเซนเซอร์อยู่ตำแหน่งเดิม

2. จดวันที่ เวลา สภาพแอร์ และแสงแดดลงบันทึก session

**เริ่มบันทึก**

3. เปิดโปรแกรม capture serial และ event logger บน laptop แล้วจ่ายไฟให้บอร์ด จดเวลาที่จ่ายไฟ (timestamp\_ms \= 0\)

4. รอ 3 นาทีให้ MQ-2 warm-up โดยห้องว่างและ LED ปิด

**ในแต่ละรอบจอง**

5. เมื่อถึงเวลาในตาราง ใช้คีมคีบตุ๊กตาผ่านประตูไปวางบนเก้าอี้ แล้วกดปุ่ม fig\_in ใน event logger

6. หลังตุ๊กตาตัวแรกเข้า เปิด LED และกด led\_on

7. ทำตามตาราง: ตัวที่มาสาย, ออกก่อน, ขยับตุ๊กตา (กด arrange)

8. เมื่อถึงเวลาจบ คีบตุ๊กตาออกทีละตัว กด fig\_out ทุกครั้ง

9. ปิด LED และกด led\_off (รอบ "ลืมปิดไฟ" ให้รอตามตารางก่อน)

**การทดสอบไฟไหม้** (เมื่อถึงเวลาในตาราง และมือไม่อยู่ในกล่อง)

10. ไฟแช็ก: จุดไฟห่างช่องหน้าต่างด้านนอก 10 cm ค้างไว้ 8–11 วินาที

11. แก๊ส: กดแก๊สไฟแช็กโดยไม่จุด ใกล้ช่องหน้าต่างฝั่ง MQ-2 นาน 2–3 วินาที

12. ธูป: ถือธูป 1 ดอกที่ช่องหน้าต่างนาน 25 วินาที

13. กดปุ่มเริ่มและจบการทดสอบใน event logger

**จบ session**

14. หลังรอบสุดท้าย รอให้ห้องว่างอย่างน้อย 4 นาที แล้วหยุด capture และบันทึกไฟล์ในชื่อ day\<N\>\_\<วันที่\>.csv

15. ดึงภาพนิ่งจาก SD card และตรวจหาตุ๊กตาที่อยู่ในมุมอับหรือของที่ลืมไว้ในกล่อง

## **7\. ผลการดำเนินการรายวัน**

รูปแต่ละวันอยู่ในหัวข้อ 7.2–7.5 ทุกรูปอ่านจากบนลงล่าง แกนนอนคือเวลานาฬิกาจริง ทุกแถวใช้แกนเวลาเดียวกัน

## **8\. ตัวอย่าง 1 รอบจอง**

![ตัวอย่าง 1 รอบ][image5]

รอบที่ 3 ของวันที่ 1 แสดงให้เห็นว่าแต่ละตัวแปรตอบสนองต่อเหตุการณ์อย่างไร

* **ตุ๊กตาจริง** (เส้นน้ำเงิน) เพิ่มทีละตัวในช่วง 30 วินาทีแรก ลดลงตอนนาทีที่ 4 และ 4.7 (ตัวหนึ่งออกก่อน อีกตัวออกไปชั่วคราว) แล้วเพิ่มกลับตอนนาทีที่ 5.7

* **กล้อง** (เส้นส้ม) ตามจำนวนจริงได้ แต่ตกลงต่ำกว่าจริงบ่อยเมื่อมี 4 ตัว

* **label** เริ่มเป็น 1 พร้อมตุ๊กตาตัวแรก และค้างต่ออีก 30 วินาทีหลังตัวสุดท้ายออก

* **LED** เปิดช้ากว่าตุ๊กตาตัวแรกไม่กี่วินาที (ผู้ทดลองต้องกดสวิตช์) และปิดก่อน label ตก

* **IR ประตู** ติดเฉพาะตอนคีบตุ๊กตาผ่านประตู ไม่ได้ติดตลอดช่วงที่มีคน

* **LDR** เป็นขั้นบันไดตามสถานะ LED และมี spike สั้น ๆ ตอนมือบังแสง

## **9\. ข้อจำกัดของการทดลอง**

1. **ตุ๊กตาไม่ปล่อยความร้อน ความชื้น และเสียง**: ในกล่อง temp\_c เปลี่ยนตาม heater ของ MQ-2, LED และแอร์ห้องแล็บ ผลเรื่องอุณหภูมิจึงนำไปใช้กับห้องจริงไม่ได้

2. **ผู้ทดลองเป็นคนเปิดปิด LED ตามจำนวนคน**: ค่าเซนเซอร์แสง (analog\_1\_raw) จึงสัมพันธ์กับ label โดยตรง ระบบจริงที่ไฟถูกสั่งโดยโมเดลจะไม่มีความสัมพันธ์นี้

3. **มือผู้ทดลองต้องเข้าไปในกล่องทุกครั้ง**: ทำให้กล้องและเซนเซอร์ประตูเห็นมือ ซึ่งไม่มีในห้องจริง

4. **ช่วงเวลาถูกย่อ**: รอบจอง 5–13 นาที สั้นกว่าการประชุมจริงมาก และมีเพียง 4 วัน

5. **แหล่งไฟร่วมกัน**: ESP32, MQ-2 และ LED ใช้ USB 5 V เส้นเดียว ทำให้บอร์ดรีเซ็ตในวันที่ 2 ควรแยกแหล่งจ่ายไฟในการเก็บจริง

6. **เป็นข้อมูลจำลอง**: พฤติกรรมเซนเซอร์มาจากแบบจำลองทางฟิสิกส์และสถิติ ต้องยืนยันด้วยข้อมูลจริงก่อนสรุปผล
