# Box-model Smart Room Dataset (ข้อมูลจำลอง)

> **ข้อมูลชุดนี้เป็นข้อมูลจำลอง (synthetic)** สร้างด้วย `make_box_dataset.py` ตาม protocol การเก็บข้อมูลในเอกสารนี้
> ใช้สำหรับพัฒนา pipeline และทดสอบโมเดลก่อนเก็บข้อมูลจริง ถ้านำไปใช้ในรายงาน ต้องระบุว่าเป็นข้อมูลจำลอง
> เมื่อเก็บข้อมูลจริงด้วย protocol เดียวกัน ให้แทนไฟล์ใน `raw/` และ `events/` แล้วรัน pipeline เดิมได้ทันที

## 1. สรุป

| รายการ | ค่า |
| --- | --- |
| ห้องจำลอง | กล่องกระดาษ 1 กล่อง แทนห้องประชุม 6 ที่นั่ง |
| คนในห้อง | ตุ๊กตากระดาษตั้งโต๊ะ สูงประมาณ 7 cm สูงสุด 6 ตัว |
| อัตราบันทึก | 2 Hz (ทุก 500 ms) |
| จำนวนวัน | 4 session (10–13 พ.ย. 2026) วันละประมาณ 3 ชั่วโมง |
| จำนวนแถว | train 64,787 (วันที่ 1–3), test 21,597 (วันที่ 4) |
| Label | `power_on` 0/1: ควรจ่ายไฟให้ห้องหรือไม่ |
| สัดส่วน label = 1 | train 0.61, test 0.60 |

## 2. ไฟล์

```
box_dataset/
├── raw/day{N}_{date}.csv          log จาก serial แบบดิบ 1 ไฟล์ต่อวัน (มีปัญหาแบบ log จริง)
├── train.csv                      วันที่ 1–3 ที่ parse แล้ว + คอลัมน์ day, boot
├── test.csv                       วันที่ 4 ที่ parse แล้ว + คอลัมน์ day, boot
├── events/day{N}_events.csv       event log ที่ผู้ทดลองจดระหว่างเก็บ (ที่มาของ label)
├── ground_truth/day{N}_truth.csv  ความจริงทุก 0.5 s (ใช้ประเมินผลเท่านั้น ห้ามใช้เป็น feature)
├── sessions.csv                   สรุปแต่ละวัน: เวลาเริ่ม, สภาพห้อง, การทดสอบที่ทำ
└── known_issues.csv               ปัญหาที่พบตอนตรวจข้อมูล พร้อมเวลา
```

`train.csv` และ `test.csv` คือ raw ที่ตัดเฉพาะบรรทัดที่ไม่ใช่ข้อมูลทิ้ง (boot log, header ซ้ำ, บรรทัดขาดครึ่ง) noise, `nan` และ `-1` ทั้งหมดยังอยู่ครบ

## 3. อุปกรณ์และการติดตั้ง

**กล่อง**: 40 × 30 × 25 cm (กว้าง × ลึก × สูง) มีช่องประตู 6 × 9 cm ที่ผนังด้านหน้า ช่องหน้าต่าง 5 × 5 cm ที่ผนังด้านหลัง และรูกล้องกลางฝากล่อง ภายในมีเก้าอี้กระดาษ 6 ตัวรอบโต๊ะกลาง

| column | เซนเซอร์ | ตำแหน่ง | หมายเหตุ |
| --- | --- | --- | --- |
| `mq2_raw` | MQ-2 (AO ผ่านตัวแบ่งแรงดัน) | ใต้ฝากล่อง | heater กินไฟ ~0.8 W ทำให้กล่องอุ่นขึ้น |
| `flame_do` | Flame sensor 1 ช่อง (DO) | ผนังหลัง หันเข้าหาช่องหน้าต่าง | active-low: 0 = เจอไฟ |
| `digital_do` | IR obstacle FC-51 (DO) | ข้างกรอบประตู ยิงขวางประตู | active-low: 0 = มีวัตถุผ่านประตู |
| `temp_c`, `humidity` | DHT22 | ผนังข้าง กลางความสูง | อ่านทุก 2 s |
| `temp_f`, `heat_index_c`, `heat_index_f` | คำนวณใน firmware | — | ใช้ Adafruit DHT library |
| `analog_1_raw` | LDR module (AO) | ผนังข้าง หันเข้าในกล่อง | ค่ามาก = มืด |
| `analog_2_raw` | Gray sensor TCRT5000 (AO) | พื้นธรณีประตู หันขึ้น | ค่ามาก = มีวัตถุอยู่เหนือ |
| `person_count` | กล้อง ESP32-S3 + FOMO ที่เทรนกับตุ๊กตา | กลางฝากล่อง มองลง | บอร์ดแยก ส่งจำนวนทาง UART ~3 fps |
| — | ไฟ LED strip 5 V | ใต้ฝากล่อง | แทนไฟห้อง เปิดปิดด้วยสวิตช์มือ |

**การตีความที่ต้องยืนยัน**: schema ไม่ได้ระบุว่า `digital_do`, `analog_1_raw`, `analog_2_raw` คือเซนเซอร์อะไร ข้อมูลชุดนี้ตีความตามแถวตัวอย่าง (`digital_do` = 1 ตอนห้องว่าง จึงเป็นเซนเซอร์ active-low, `analog_1_raw` ลดจาก 950 เป็น 650–700 ตอนมีไฟลุก จึงเป็นเซนเซอร์แสง) ถ้าใช้เซนเซอร์ต่างจากนี้ ให้แก้ส่วน "IR obstacle", "LDR" และ "gray sensor" ใน `make_box_dataset.py`

**Logger**: ESP32 DevKit พิมพ์ CSV ทาง USB serial 115200 baud ไปที่ laptop บันทึกเป็นไฟล์ 1 ไฟล์ต่อ session `timestamp_ms` คือ `millis()` นับจากบอร์ดเปิด จึงเริ่มใหม่ทุกครั้งที่บอร์ดรีเซ็ต

**แหล่งไฟ**: ESP32, MQ-2 heater และ LED ใช้ไฟ USB 5 V เส้นเดียวกัน (เป็นสาเหตุของ brownout วันที่ 2 ควรแยกแหล่งจ่ายไฟ LED ในการเก็บจริง)

## 4. Protocol การเก็บข้อมูล (ต่อ 1 session)

1. วางกล่องบนโต๊ะห้องแล็บ ห่างหน้าต่างประมาณ 2 m จดสภาพห้อง (แอร์ แสงแดด) ลง `sessions.csv`
2. เปิดไฟเลี้ยงบอร์ดพร้อมเริ่ม capture serial และเริ่ม event logger บน laptop บันทึกเวลานาฬิกาตอนเริ่ม
3. รอ MQ-2 warm-up 3 นาที โดยห้องว่างและปิด LED
4. เล่น scenario การจองห้องประมาณ 11 รอบต่อ session:
    - ผู้ทดลองใช้คีมยาวคีบตุ๊กตาเข้าทางประตูทีละตัว ห่างกัน 3–15 วินาที บางตัวมาสาย 1–3 นาที
    - กดปุ่ม `fig_in` / `fig_out` ใน event logger ทุกครั้งที่ตุ๊กตาผ่านประตู
    - เปิด LED หลังตุ๊กตาตัวแรกเข้า และปิดหลังตัวสุดท้ายออก (บางรอบตั้งใจลืมปิดไฟ 2–6 นาที)
    - แต่ละรอบใช้ห้อง 5–13 นาที แล้วเว้นห้องว่าง 3–9 นาที
    - มีกรณีพิเศษ: ออกก่อน, ออกแล้วกลับเข้ามา, กลุ่มถัดไปเข้าทันที, ขยับตุ๊กตาโดยจำนวนไม่เปลี่ยน
5. ทดสอบเซนเซอร์ไฟไหม้ 1–3 ครั้งต่อ session ตอนไม่มีมือในกล่อง:
    - `flame`: จุดไฟแช็กห่างช่องหน้าต่างด้านนอกประมาณ 10 cm นาน 8–11 วินาที
    - `gas`: กดแก๊สไฟแช็ก (ไม่จุด) ใกล้ MQ-2 นาน 2–3 วินาที
    - `smoke`: ถือธูป 1 ดอกที่ช่องหน้าต่างนาน 25 วินาที
    - **ความปลอดภัย**: ห้ามนำเปลวไฟเข้าในกล่องกระดาษ ทดสอบห่างจากกล่องอย่างน้อย 10 cm มีถังน้ำหรือถังดับเพลิงขนาดเล็กอยู่ใกล้ และมีผู้ทดลองอย่างน้อย 2 คน
6. ปิดเครื่องเมื่อห้องว่างอย่างน้อย 4 นาทีหลังรอบสุดท้าย
7. กล้องบันทึกภาพนิ่งลง SD card ทุก 10 วินาที เพื่อใช้ตรวจย้อนหลัง (ใช้หาตุ๊กตาที่อยู่ในมุมอับ และของที่ลืมไว้ในกล่อง)

**การแบ่ง train/test**: แบ่งตามวัน วันที่ 1–3 เป็น train และวันที่ 4 เป็น test วันทดสอบมีสภาพที่ไม่เคยเจอใน train (แดดส่องเป็นช่วง ๆ) เพื่อดูว่าโมเดลรับมือกับสภาพใหม่ได้หรือไม่

## 5. Column dictionary

| column | ชนิด | ช่วงค่าในข้อมูล | ค่าพิเศษ |
| --- | --- | --- | --- |
| `day` | int | 1–4 | เฉพาะ train/test |
| `boot` | int | 0–1 | เฉพาะ train/test: เพิ่มขึ้นเมื่อ `timestamp_ms` เริ่มใหม่ |
| `timestamp_ms` | int (ms) | ~2,500 ถึง ~11,000,000 | ปกติห่างกัน 500 บางครั้ง 501 หรือ 1,000 (บรรทัดหาย) |
| `mq2_raw` | int (ADC 12-bit) | 289–1,847 | ห้องว่างปกติ 300–360, ช่วง warm-up สูงถึง ~590 |
| `flame_do` | 0/1 | | 0 = เจอไฟ |
| `digital_do` | 0/1 | | 0 = มีวัตถุที่ประตู |
| `temp_c` | float (°C) | 25.8–33.2 | `nan` = อ่าน DHT22 ไม่สำเร็จ, ค่าซ้ำ 4 แถวติดกัน |
| `humidity` | float (%RH) | 49–71 | เหมือน `temp_c` |
| `temp_f` | float (°F) | | `temp_c × 1.8 + 32` |
| `heat_index_c`, `heat_index_f` | float | | สูตร Adafruit `computeHeatIndex()` |
| `analog_1_raw` | int (ADC) | 211–1,201 | LED เปิด ~280, LED ปิด ~750–1,000 |
| `analog_2_raw` | int (ADC) | 282–3,297 | ปกติ ~300, มีมือหรือตุ๊กตาผ่าน 1,500–3,300 |
| `alarm` | 0/1 | | firmware: `flame_do == 0` หรือ `mq2_raw > 700` |
| `person_count` | int | 0–6 | `-1` = กล้องไม่ส่งข้อมูล |
| `power_on` | 0/1 | | **label** |

## 6. Label `power_on`

`power_on` = 1 ตั้งแต่ event `fig_in` ตัวแรก จนถึง 30 วินาทีหลัง event `fig_out` ที่ทำให้ห้องว่าง ถ้ากลุ่มใหม่เข้าภายใน 30 วินาที label จะเป็น 1 ต่อเนื่อง

- label มาจาก event log ไม่ได้มาจากเซนเซอร์ใด ๆ จึงไม่เกิด label leakage จากตัว feature
- เวลาใน event log ช้ากว่าเหตุการณ์จริง 0.2–1.2 วินาที (เวลาที่ใช้กดปุ่ม) ทำให้ label ตรงขอบช่วงคลาดได้ 1–3 แถว (`ground_truth/*_truth.csv` มี `power_on_true` สำหรับเปรียบเทียบ)
- label **ไม่รวม** เรื่องไฟไหม้ การสั่งรีเลย์จริงควรเป็น `relay = power_on_pred AND alarm == 0` โดย alarm เป็น hard rule นอกโมเดล

## 7. สิ่งที่ต้องจัดการก่อนใช้

1. **Boot log และ header ซ้ำ** (วันที่ 2): parser ต้องข้ามบรรทัดที่ไม่มี 14 ช่อง และบรรทัดที่ขึ้นต้นด้วย `timestamp_ms`
2. **`timestamp_ms` เริ่มใหม่** (วันที่ 2): ใช้คอลัมน์ `boot` หรือตรวจจาก `diff() < 0` ก่อนทำ rolling/lag ห้ามคำนวณข้ามช่วง boot
3. **MQ-2 warm-up**: 3 นาทีแรกของทุก session และหลัง reboot ค่า `mq2_raw` สูงกว่าปกติ ควรตัดทิ้งหรือ flag ไว้
4. **`nan` และ `-1`**: แปลงเป็น NaN ก่อนคำนวณสถิติ
5. **`analog_1_raw` สะท้อนสถานะ LED** ซึ่งผู้ทดลองเปิดตามจำนวนตุ๊กตา เป็นตัวแทนของ label ที่รั่ว (leak) ใช้ได้ดีในข้อมูลชุดนี้ แต่ใช้ไม่ได้เมื่อไฟถูกสั่งโดยระบบเอง (จะกลายเป็น "ไฟเปิด เพราะโมเดลสั่งเปิด") ควรใช้เพื่อตรวจจับ "ลืมปิดไฟ" แทน
6. **ตุ๊กตาไม่ปล่อยความร้อน เสียง หรือความชื้น**: `temp_c` และ `humidity` เปลี่ยนตาม heater ของ MQ-2, LED, แอร์ห้องแล็บ และการเปิดประตู ไม่ได้เปลี่ยนตามจำนวนคน ต่างจากห้องจริง ต้องระบุข้อจำกัดนี้ในรายงาน
7. **กล้องผิดพลาดเป็นช่วงยาว**: ตุ๊กตาในมุมอับทำให้นับขาดทั้งช่วง และของที่ลืมไว้ในกล่องทำให้นับเกินหลายนาที (ดู `known_issues.csv`) ต้องใช้เซนเซอร์ประตูช่วยยืนยัน
8. **Alarm หลอกในวันทดสอบ**: แดดทำให้ `flame_do` = 0 ชั่วขณะ 7 ครั้ง ไม่มีใน train ควร debounce ก่อนใช้ (เช่น ต้องติดต่อเนื่อง ≥ 2 วินาที)

## 8. ข้อความสำหรับ declare ในรายงาน

> ข้อมูลที่ใช้ในการพัฒนาโมเดลเป็นข้อมูลจำลอง (synthetic data) ที่สร้างขึ้นตาม protocol การเก็บข้อมูลจากห้องประชุมจำลองด้วยกล่องกระดาษขนาด 40 × 30 × 25 cm ซึ่งติดตั้งเซนเซอร์ MQ-2, flame sensor, DHT22, LDR, IR obstacle sensor, gray sensor และกล้อง ESP32-S3 ที่ตรวจนับตุ๊กตาด้วยโมเดล FOMO ข้อมูลบันทึกที่อัตรา 2 Hz เป็นเวลา 4 session (session ละประมาณ 3 ชั่วโมง) รวม 86,384 แถว แบบจำลองครอบคลุมพฤติกรรมของเซนเซอร์ ได้แก่ การ warm-up ของ MQ-2, การอ่านค่า DHT22 ทุก 2 วินาที, ความคลาดเคลื่อนของกล้อง (การบัง, มุมอับ, false positive), noise ของ ADC และปัญหาของ logger (การรีเซ็ตของบอร์ด, บรรทัดข้อมูลหาย) label `power_on` กำหนดจาก event log ของผู้ทดลอง โดยเป็น 1 ขณะมีคนอยู่ในห้องและต่อเนื่องอีก 30 วินาทีหลังห้องว่าง การแบ่งข้อมูลใช้ 3 session แรกเป็นชุดฝึก และ session ที่ 4 ซึ่งมีสภาพแสงต่างออกไปเป็นชุดทดสอบ

เมื่อเก็บข้อมูลจริงแล้ว ให้ตัดประโยคแรกออก แล้วแทนด้วยวันที่และจำนวนแถวจริง

## 9. สร้างข้อมูลใหม่

```bash
pip install numpy pandas scipy
python3 make_box_dataset.py          # สร้างโฟลเดอร์ box_dataset/ ใหม่ทั้งหมด
```

ปรับได้ที่ `DAYS` (ตารางวัน, สภาพห้อง, การทดสอบ, กรณีพิเศษ), `GRACE_S`, `MQ2_ALARM` และฟังก์ชันเซนเซอร์แต่ละตัวใน `simulate()` ทุกวันใช้ `seed` คงที่ จึงได้ผลเดิมทุกครั้งที่รัน
